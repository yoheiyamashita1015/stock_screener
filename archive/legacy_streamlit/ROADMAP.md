# 個人開発学習ロードマップ
## 米国株スクリーナーを題材にしたITスキル習得計画

---

## 現在の技術スタック

- **言語**: Python 3.12
- **UI**: Streamlit
- **データ取得**: yfinance（Yahoo Finance API）
- **分析**: pandas / numpy / plotly
- **キャッシュ**: pickle / JSON ファイル

---

## Phase 1｜品質の基盤をつくる（目安: 1〜2ヶ月）

### 目標
「動くコード」から「信頼できるコード」へ。チーム開発でも通用する品質意識を身につける。

### 1-1. ユニットテスト（pytest）

**実装内容**
- `tests/` ディレクトリを作成し、各モジュールのテストを書く
- `src/screener.py` の `_check_range` や `_matches_criteria` をテスト
- `src/fundamental.py` の各計算関数をテスト
- モックを使って yfinance への通信をテストから切り離す

**学習ポイント**
- テストの書き方（AAA: Arrange / Act / Assert）
- モック・スタブの使い方（`unittest.mock`）
- カバレッジ計測（`pytest-cov`）
- パラメータ化テスト（`@pytest.mark.parametrize`）

**身につくスキル**
- バグを早期発見する習慣
- リファクタリングを安全に行う能力
- コードの仕様をテストで表現する力

---

### 1-2. CI/CD（GitHub Actions）

**実装内容**
- GitHubリポジトリを作成してコードをpush
- `.github/workflows/test.yml` を作成
- mainブランチへのpush時に pytest が自動実行されるようにする
- コードスタイルチェック（flake8 / ruff）を追加

**学習ポイント**
- YAMLでワークフローを定義する
- 仮想環境のセットアップ・依存関係のキャッシュ
- ブランチ戦略（main / develop / feature）

**身につくスキル**
- 「コードをpushするたびに自動でテストが走る」環境の構築
- チーム開発の標準的なフロー

---

## Phase 2｜データ基盤を強化する（目安: 2〜3ヶ月）

### 目標
ファイルベースのキャッシュをデータベースに置き換え、データ管理の本質を学ぶ。

### 2-1. データベース設計（SQLite → PostgreSQL）

**実装内容**
- 現在のpickle/JSONキャッシュをSQLiteに移行
- テーブル設計:
  ```
  stocks          ... 銘柄マスタ（ticker, name, sector, exchange）
  fundamentals    ... ファンダメンタルデータ（取得日時付き）
  price_history   ... 株価履歴
  screening_runs  ... スクリーニング実行履歴
  screening_results ... スクリーニング結果
  ```
- SQLAlchemy（ORMライブラリ）を使ってPythonからDBを操作
- 慣れたらPostgreSQLに移行（Dockerで起動）

**学習ポイント**
- テーブル設計・正規化・インデックス
- SQLの基本（SELECT / INSERT / UPDATE / JOIN）
- マイグレーション（Alembic）
- ORMとRAW SQLの使い分け

**身につくスキル**
- 業務システム開発で必須のDB知識
- データの整合性・トランザクションの概念

---

### 2-2. データパイプライン（定期バッチ処理）

**実装内容**
- 毎日決まった時刻に株価データをDBに取り込むバッチを作成
- スケジューラー（APScheduler または cron）で自動実行
- 取得失敗時のリトライ・エラーログ記録

**学習ポイント**
- バッチ処理の設計（冪等性: 何度実行しても同じ結果になること）
- ログ設計（logging モジュール）
- エラーハンドリングと通知

**身につくスキル**
- データエンジニアリングの基礎
- 定期処理・監視の設計

---

## Phase 3｜APIサーバーを構築する（目安: 2〜3ヶ月）

### 目標
StreamlitのUIに依存しないバックエンドAPIを設計・実装する。

### 3-1. REST API（FastAPI）

**実装内容**
- `api/` ディレクトリを作成してFastAPIアプリを構築
- エンドポイント設計:
  ```
  GET  /api/stocks                    ... 銘柄一覧
  GET  /api/stocks/{ticker}           ... 個別銘柄情報
  POST /api/screen                    ... スクリーニング実行
  GET  /api/screen/{job_id}           ... スクリーニング結果取得
  GET  /api/presets                   ... プリセット一覧
  POST /api/presets                   ... プリセット保存
  DELETE /api/presets/{name}          ... プリセット削除
  POST /api/backtest                  ... バックテスト実行
  ```
- Pydanticによるリクエスト・レスポンスのバリデーション
- Swagger UI（/docs）で自動ドキュメント生成

**学習ポイント**
- REST設計原則（リソース設計・HTTPメソッドの使い分け）
- Pydanticによる型安全な設計
- 依存性注入（Depends）
- エラーレスポンスの設計

**身につくスキル**
- バックエンドエンジニアの基本スキル
- フロントエンドと分離したシステム設計

---

### 3-2. 認証・認可（JWT）

**実装内容**
- ユーザー登録・ログインAPIを追加
- JWTトークンによる認証
- プリセットをユーザーごとに管理

**学習ポイント**
- 認証（Authentication）と認可（Authorization）の違い
- JWTの仕組み（Header / Payload / Signature）
- パスワードのハッシュ化（bcrypt）

**身につくスキル**
- セキュリティの基礎
- Webアプリ開発で必ず登場する認証フロー

---

## Phase 4｜コンテナ化とクラウドへ（目安: 2〜3ヶ月）

### 目標
ローカルでしか動かないアプリを、インターネットからアクセスできる状態にする。

### 4-1. Docker化

**実装内容**
- `Dockerfile` を作成（Streamlit UI用 / FastAPI用）
- `docker-compose.yml` でDB・API・UIをまとめて起動
- 環境変数による設定管理（`.env` ファイル）

**学習ポイント**
- Dockerイメージ・コンテナの概念
- レイヤーキャッシュを意識したDockerfileの書き方
- マルチコンテナ構成（docker-compose）
- ボリュームマウント・ネットワーク設定

**身につくスキル**
- 「自分のPCでしか動かない」問題の解決
- 環境差異をなくす再現性の確保

---

### 4-2. クラウドデプロイ（AWS または GCP）

**実装内容（AWSの場合）**
- ECRにDockerイメージをpush
- ECS（Fargate）でAPIサーバーを起動
- RDS（PostgreSQL）をDBとして使用
- S3にスクリーニング結果CSVを保存
- CloudWatchでログ・メトリクスを監視

**学習ポイント**
- VPC・サブネット・セキュリティグループ（ネットワーク基礎）
- IAMによる権限管理
- ロードバランサー（ALB）
- インフラのコード化（Terraform または AWS CDK）

**身につくスキル**
- クラウドエンジニア・インフラエンジニアの基礎
- 転職市場で差がつく実践的なAWS経験

---

## Phase 5｜機械学習で予測モデルを作る（目安: 3〜4ヶ月）

### 目標
バックテストで蓄積したデータを使って、リターン予測モデルを構築する。

### 5-1. 特徴量エンジニアリングとモデル構築

**実装内容**
- バックテスト結果をDBに蓄積
- 特徴量の設計:
  ```
  ファンダメンタル: PER / PBR / ROE / ROA / 売上成長率 / EPS成長率 / FCF利回り
  テクニカル: RSI / SMA乖離率 / 52週高値乖離 / モメンタム
  マクロ: 業種 / 時価総額区分
  ```
- 目的変数: 3ヶ月後・6ヶ月後のリターン（分類 or 回帰）
- LightGBMで学習・評価
- 特徴量重要度の可視化

**学習ポイント**
- 訓練・検証・テストデータの分割
- 時系列データでのリーク防止（未来データを使わない）
- 過学習の検出と対策
- シャープレシオ・最大ドローダウンによるモデル評価

**身につくスキル**
- データサイエンティストの核心スキル
- 金融データ特有の注意点（非定常性・リーク）

---

### 5-2. モデルのAPI化とStreamlitへの統合

**実装内容**
- 学習済みモデルを保存（joblib / mlflow）
- FastAPI経由で予測APIを公開
- スクリーニング結果に「AIスコア」列を追加して表示

**学習ポイント**
- MLflowによるモデル管理（バージョン管理・実験管理）
- 推論APIの設計
- A/Bテスト的な考え方（モデル更新時の比較）

**身につくスキル**
- MLOps（機械学習の運用）の入口
- データサイエンスとエンジニアリングの橋渡し

## 学習を継続するためのコツ

1. **1フェーズを完全に終わらせなくても次に進んでよい**
   完璧主義は停滞の原因。7割できたら次へ進み、後から戻る。

2. **GitHubに公開してポートフォリオにする**
   READMEに「何を作ったか・何を学んだか」を書くことで
   転職・副業時に実績として提示できる。

3. **エラーはドキュメントを読んで解決する習慣をつける**
   公式ドキュメントを読む力は、どの言語・フレームワークでも通用する。

4. **このシステムで動くものを作り続ける**
   チュートリアルを何周しても実力はつかない。
   実際に動くシステムを育てることが最速の学習。
